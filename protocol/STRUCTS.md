# Structures and serialization

All scalar builders in `common/shroud/wire.h` write little-endian bytes. Text is terminated with a NUL byte. Delimited preview tokens are escaped against the protocol separators before serialization.

The selection envelope contains keeper spawn ID followed by two zero DWORDs and a NUL-terminated selection tree. Template details contain template ID, a DWORD value 1, and a NUL-terminated caret-delimited string containing ID/name/description, class, level, resource maxima, seven independent attributes, ability count and rank/title-string pairs, then equipment count and item/name pairs. The implementation is the authoritative schema; do not use native C++ struct padding for these variable payloads.

Equipment preview uses the RoF2 ordinary serialized ItemPtr service without an ItemPacket-type DWORD. Inventory containers are treated separately from the preview cache. Bank action envelopes validate fixed lengths and keeper/menu context before inspecting or retrieving anything. Recovery/removal remains available separately from new-entry enablement.

The normal RoF2 player profile marks alternate profile use and the shroud template. Its native resource/stat tail is generated by `common/shroud/native_stats.h`; server resource baselines are recovered by `resource_baseline.h`. Displayed AC/attack are not automatically internal combat contributions.

## Recovered, not implemented: native transform

Opcode `0x6562` begins with spawn ID (DWORD) and a 16-bit profile offset. The prefix is followed by the normally encoded single-spawn body; the profile offset is six bytes plus that variable body length. Observers use the spawn update path. The self path carries a compact 0x4ff8-byte profile followed by a DWORD inventory count and ordinary serialized inventory roots/children. It does not add an ItemPacket-type DWORD.

The self parser applies profile, spawn and inventory, refreshes state and sends an empty completion message at candidate `0x7786`. That acknowledgement has no revision token and is **not mapped/handled by this release**. Active-buff nested bytes and a safe complete in-place server cache exchange still require implementation/validation. The current server deliberately uses its committed-state zone-reload path instead. Do not enable an experimental transform merely because the opcode is registered.
